# 🔍 성능 테스트 및 검증 스크립트

## 성능 테스트 방법

### 1. 개발 도구 준비
1. Chrome DevTools 열기 (F12)
2. Console 탭과 Profiler 탭 준비
3. React Developer Tools 설치 필요

### 2. Starter 프로젝트 테스트 (성능 문제 버전)

```bash
cd starter
npm run dev
```

브라우저에서 http://localhost:5173 열기

**콘솔에서 확인할 것들:**
- 🔄 필터링 로직 실행됨 - 필터 변경 시마다 출력
- 🔄 통계 계산됨 - 매번 새로운 계산
- 🔄 UserDashboard 렌더링됨 (성능 문제 버전) - 불필요한 리렌더링
- 🔄 UserFilter 렌더링됨 - 빈번한 리렌더링
- 🔄 UserCard [ID] 렌더링됨 - 모든 카드가 리렌더링

**성능 문제 재현:**
1. 검색어 입력 시 모든 컴포넌트 리렌더링
2. 부서 필터 변경 시 불필요한 계산 반복
3. 활성 사용자 토글 시 전체 목록 리렌더링

### 3. Solution 프로젝트 테스트 (최적화 버전)

```bash
cd solution  
npm run dev
```

브라우저에서 http://localhost:5174 열기

**콘솔에서 확인할 것들:**
- ✅ UserDashboard 렌더링됨 (최적화 버전) - 필요한 경우만 렌더링
- ✅ UserFilter 렌더링됨 (최적화 버전) - useShallow로 최적화
- ✅ UserCard [ID] 렌더링됨 (메모이제이션) - React.memo로 최적화

**성능 개선 확인:**
1. 검색어 입력 시 관련 컴포넌트만 리렌더링
2. 필터 변경 시 메모이제이션된 계산 결과 사용
3. 개별 카드는 변경될 때만 리렌더링

### 4. 성능 비교 측정

#### React DevTools Profiler 사용:
1. Profiler 탭에서 녹화 시작
2. 필터 조작 (검색, 부서 변경, 정렬)
3. 녹화 중지 후 결과 분석

**측정 항목:**
- 전체 렌더링 시간
- 컴포넌트별 렌더링 횟수
- 불필요한 리렌더링 감소율

#### 콘솔 로그 기반 비교:
- Starter: 필터 변경 시 10+ 개의 렌더링 로그
- Solution: 필터 변경 시 2-3개의 렌더링 로그

### 5. 메모리 사용량 테스트

#### Performance 탭 사용:
1. Memory 체크박스 활성화
2. 녹화 시작
3. 반복적인 필터링 작업 수행
4. 메모리 사용 패턴 비교

### 6. 성능 개선 요약

| 구분 | Starter (문제 버전) | Solution (최적화 버전) |
|------|-------------------|---------------------|
| 렌더링 횟수 | 필터링 시 전체 리렌더링 | 필요한 컴포넌트만 렌더링 |
| 계산 최적화 | 매번 새로운 계산 | 메모이제이션된 셀렉터 |
| 컴포넌트 최적화 | 일반 함수형 컴포넌트 | React.memo 적용 |
| 구독 최적화 | 전체 스토어 구독 | useShallow로 선택적 구독 |

### 7. 추가 성능 테스트

- 사용자 수를 1000명으로 증가

**연속 조작 테스트:**
- 빠른 타이핑으로 검색어 입력
- 렌더링 디바운싱 효과 확인
