## 🔧 핵심 구현 포인트

### 1. Zustand 스토어 설계 (`memoStore.js`)

#### 기본 상태 구조

```javascript
const initialState = {
  memos: [], // 메모 목록
  filter: 'all', // 현재 필터
  searchTerm: '', // 검색어
};
```

**설계 이유:**

- 단순하고 명확한 상태 구조로 이해하기 쉬움
- 각 상태는 독립적이면서도 조합 가능한 구조

#### 액션 구현 패턴

```javascript
// 1. 메모 추가 - ID 생성과 타임스탬프 처리
addMemo: (memo) => set((state) => ({
  memos: [...state.memos, {
    ...memo,
    id: Date.now(),
    createdAt: new Date().toISOString(),
    updatedAt: new Date().toISOString(),
  }],
})),

// 2. 메모 업데이트 - 불변성 유지
updateMemo: (updatedMemo) => set((state) => ({
  memos: state.memos.map((memo) =>
    memo.id === updatedMemo.id ? updatedMemo : memo
  ),
})),

// 3. 메모 삭제 - filter 메서드 활용
deleteMemo: (id) => set((state) => ({
  memos: state.memos.filter((memo) => memo.id !== id),
})),
```

**핵심 포인트:**

- `set` 함수로 불변성 유지
- 스프레드 연산자로 배열/객체 복사
- ID는 `Date.now()`로 간단하게 생성 (실제 프로젝트에서는 UUID 권장)

#### 계산된 값 (Computed Values)

```javascript
// 필터링된 메모 목록 - 두 조건을 동시에 적용
filteredMemos: (state) => {
  return state.memos.filter((memo) => {
    // 카테고리 필터링
    const matchesCategory = state.filter === 'all' || memo.category === state.filter;

    // 검색어 필터링 (제목 + 내용)
    const matchesSearch =
      memo.title.toLowerCase().includes(state.searchTerm.toLowerCase()) ||
      memo.content.toLowerCase().includes(state.searchTerm.toLowerCase());

    return matchesCategory && matchesSearch;
  });
},

// 통계 정보 - get 함수로 다른 계산된 값 참조
statistics: (state) => {
  const filtered = state.filteredMemos;
  const byCategory = {};

  // 카테고리별 개수 집계
  state.memos.forEach((memo) => {
    byCategory[memo.category] = (byCategory[memo.category] || 0) + 1;
  });

  return {
    total: state.memos.length,
    filtered: filtered.length,
    byCategory,
  };
},
```

**설계 이유:**

- 컴포넌트에서 필터링 로직을 분리하여 재사용성 향상
- `get` 함수로 계산된 값들 간의 의존성 처리
- 통계 정보를 별도 계산으로 성능 최적화

### 2. 셀렉터 패턴 활용

#### 단일 값 셀렉터

```javascript
// 기본 패턴 - 필요한 상태만 구독
const filter = useMemoStore(state => state.filter);
const searchTerm = useMemoStore(state => state.searchTerm);
```

#### 복합 셀렉터 - 객체 반환

```javascript
// 여러 값과 액션을 함께 구독
const { filteredMemos, deleteMemo, updateMemo } = useMemoStore(state => ({
  filteredMemos: state.filteredMemos,
  deleteMemo: state.deleteMemo,
  updateMemo: state.updateMemo,
}));
```

#### 계산된 값 셀렉터

```javascript
// 통계 정보 구독
const stats = useMemoStore(state => state.statistics);

// 카테고리별 개수 표시에 활용
<span className={styles.count}>{stats.byCategory[filter.key] || 0}</span>;
```

**성능 최적화 포인트:**

- 컴포넌트는 필요한 상태만 구독하여 불필요한 리렌더링 방지
- 계산된 값은 의존성이 변경될 때만 재계산됨

### 3. 실시간 검색 구현 (디바운스)

```javascript
// MemoSearch 컴포넌트의 디바운스 구현
const [inputValue, setInputValue] = useState('');

useEffect(() => {
  const timer = setTimeout(() => {
    setSearchTerm(inputValue); // Zustand 액션 호출
  }, 300);

  return () => clearTimeout(timer);
}, [inputValue, setSearchTerm]);
```

**구현 이유:**

- 사용자가 타이핑할 때마다 필터링하면 성능 저하
- 300ms 지연으로 타이핑 완료 후 검색 실행
- cleanup 함수로 이전 타이머 정리

## 🔍 성능 최적화 전략

### 1. 셀렉터 최적화

- 컴포넌트별 필요한 상태만 구독
- 계산된 값은 Zustand 스토어에서 관리
- 복잡한 연산은 의존성 변경 시에만 실행

### 2. 리렌더링 최소화

- `React.memo` 없이도 Zustand 셀렉터로 최적화
- 로컬 상태와 글로벌 상태 적절히 분리

### 3. 디바운스로 과도한 API 호출 방지

- 검색어 입력 시 즉시 반영하지 않고 지연 적용
- 타이핑 완료 후에만 필터링 실행

## 📚 확장 가능한 아키텍처

### 1. 추가 기능 구현 방향

- **태그 시스템**: 메모에 여러 태그 추가 기능
- **정렬 기능**: 날짜, 제목, 카테고리별 정렬
- **즐겨찾기**: 중요한 메모 북마크 기능
- **드래그 앤 드롭**: 카테고리 간 메모 이동

### 2. 데이터 영속화

```javascript
// localStorage와 연동
const useMemoStore = create(
  persist(
    (set, get) => ({
      // ... 기존 스토어 로직
    }),
    {
      name: 'memo-storage',
      storage: createJSONStorage(() => localStorage),
    }
  )
);
```

### 3. 미들웨어 활용

- **devtools**: 개발 시 상태 변화 추적
- **persist**: 브라우저 저장소 연동
- **immer**: 더 편리한 불변성 관리
