# 비동기 작업 처리 - 시작 프로젝트

이 프로젝트는 Zustand를 사용한 비동기 상태 관리의 **문제점들**을 의도적으로 포함하고 있습니다.
실제로 실행해보면서 어떤 문제들이 있는지 파악해보세요!

## 🚨 현재 프로젝트의 문제점들

### 1. 로딩 상태 관리 부재
- [ ] API 호출 중에 로딩 인디케이터가 표시되지 않음
- [ ] 사용자가 언제 데이터가 로딩 중인지 알 수 없음
- [ ] 버튼을 여러 번 클릭할 수 있어서 중복 요청 발생

### 2. 에러 처리 부족
- [ ] API 호출 실패 시 사용자에게 알림이 없음
- [ ] HTTP 상태 코드 체크가 없음 (404, 500 등)
- [ ] 네트워크 오류 시 재시도 메커니즘 없음

### 3. 사용자 경험 문제
- [ ] 폼 제출 후 성공/실패 피드백이 alert로만 표시됨
- [ ] 검색 기능에 디바운싱이 없어서 매 타이핑마다 필터링
- [ ] 삭제 중 상태 표시가 없어서 중복 클릭 가능

### 4. 성능 및 최적화 부족
- [ ] 캐싱 전략이 없어서 매번 API 호출
- [ ] 중복 요청 방지 로직 없음
- [ ] 낙관적 업데이트 미적용

## 🎯 실습 과제

프로젝트를 실행한 후 다음 상황들을 직접 경험해보세요:

1. **로딩 상태 확인**
   - 새로고침 버튼을 클릭했을 때 로딩 표시가 있는가?
   - 사용자 상세보기를 클릭했을 때 로딩 중임을 알 수 있는가?

2. **에러 상황 테스트**
   - 네트워크를 끊고 새로고침해보기
   - 존재하지 않는 사용자 ID로 직접 접근해보기

3. **사용자 경험 평가**
   - 사용자 생성 버튼을 빠르게 여러 번 클릭해보기
   - 검색창에 빠르게 타이핑해보기
   - 사용자 삭제 버튼을 여러 번 클릭해보기

## 실행 방법

```bash
# 패키지 설치
npm install

# 개발 서버 시작
npm run dev

# 빌드 테스트
npm run build
```
